One system

Ten parts, one loop.

Not a chat box with extras — every capability reads and writes the same memory, the same World model, and the same history. Live answers need a gateway with a provider key (shared or your own); without one, MetaIoid says so and runs its on-device demo engine instead.

Conversational AI

Streaming replies over a task-aware model router, with failover when a model dies mid-stream. Short questions get fast models; hard ones get smart ones.

Voice

Spoken conversations with interruption handling and turn detection, in English, Hindi and Hinglish. Interrupt mid-sentence — the old reply stops.

Needs the browser microphone permission.

Vision

Live camera, stills and screen understanding through vision-capable models — with an explicit demo state until one is connected, never a faked result.

Needs the browser camera permission for live input.

Research

Collectors gather and correlate findings with confidence grading, then export real reports. Cross-checks keep extracts honest.

Coding

Code questions are classified and routed to coding-capable models, with artifacts — documents, decks, files — built, validated and downloadable.

Files

Attachments, generated files and avatars live in private per-user storage, reachable only through short-lived signed links minted after an ownership check.

Memory

A durable, categorised memory vault scoped to your account. The agent reads only what you keep — and it survives reloads.

Agentic actions

Objectives become task graphs — plan, execute, retry, pause, resume, cancel. Budgets, approvals and checkpoints are enforced in code, not by the model.

Tools & integrations

Connect your own provider keys and install skills that extend what the agent can do — each with explicit permissions and an audit trail.

Proactive assistance

Scheduled skill runs and mission follow-ups keep work moving. Schedules are registered openly and fire explicitly — nothing runs behind your back.

MetaIoid World

An ecosystem that remembers what matters.

World keeps a structured model of your life with the system — not a pile of chat logs, but entities and relationships with confidence levels, isolated per user. The agent works against this context, so every conversation starts where the last one left off.

How it works

Notice → Understand → Decide → Act → Verify → Report.

Every turn through MetaIoid follows the same six-stage sequence — whether it is a one-line answer or a week-long mission.

Notice

Your message, voice, camera frame or scheduled trigger arrives. Permissions stay with the browser; the gateway only receives what you send.

Understand

The context engine assembles memory, preferences and World entities, and classifies what the task needs — fast, smart, vision, or code.

Decide

The router picks the model and the plan. Anything consequential pauses for your approval before it runs.

Act

Tools, skills and mission tasks execute under per-account budgets — streaming progress as it happens.

Verify

A verification pass scores the output and flags placeholders, so “done” arrives with evidence behind it.

Report

The answer streams back; missions file reports; the finished turn is persisted to your history — or recorded as cancelled if interrupted.

Trust & performance

Private first, honest always.

No invented benchmarks below — one measured figure, published with its method, and architecture you can inspect in the repository.

Privacy

Provider keys live in the gateway’s environment — the browser bundle contains none. User data sits behind owner-only row-level security in Postgres; files sit in private buckets. This marketing page loads zero third-party scripts, fonts, or trackers.

Reliability

Dead models are quarantined and skipped, rate limits roll to the next candidate, and bad credentials fail fast with a plain message. Four visible connection states mean the app never performs being online.

Verification

Answers pass a verification check; missions carry checkpoints and evidence; consequential tool calls wait for approval; every skill install is validated and audited before it can run.

Readiness

Runs as an on-device demo with no accounts, on your machine with a local gateway, self-hosted with Postgres and Supabase Auth, or as this very deployment — app and API from one project.

Measured gateway throughput on a small 2‑vCPU machine against the local data driver at 64 concurrent requests — published with its method, bottlenecks and caveats, never as a user count. Your deployment’s numbers will differ; the method travels with the repo so you can re-run it.
